# 🌻 우리반 칭찬릴레이 — "이 친구는 누구일까요?" (Vercel 배포판)

React(Vite) 화면 + Vercel 서버 함수 + Upstash Redis(데이터 저장) + Gemini(AI 요약)로 구성되어 있습니다.
기존 Google Apps Script / 구글 시트는 더 이상 필요 없습니다.

## 배포 순서

### 0. (먼저!) 노출된 API 키 폐기
대화창에 붙여넣은 Gemini API 키는 이미 노출된 것으로 보고, Google AI Studio(aistudio.google.com) > API 키에서
**기존 키를 삭제하고 새 키를 발급**하세요. 새 키는 GitHub나 코드 어디에도 적지 말고 2번에서 Vercel에만 입력합니다.

### 1. GitHub에 올리기
1. github.com > New repository > 이름 `praise-relay`, **Private** 선택 > Create
2. 이 폴더의 압축을 풀고, 저장소 화면에서 `uploading an existing file`(또는 Add file > Upload files) 클릭
3. 압축 푼 폴더 **안의 파일과 폴더 전체**(api, src, package.json, index.html …)를 드래그해서 올리기
   - `package.json`이 저장소 맨 바깥(루트)에 보여야 합니다.
4. Commit changes

### 2. Vercel에 프로젝트 만들기
1. vercel.com > GitHub 계정으로 로그인 > Add New > Project
2. `praise-relay` 저장소 Import (Framework는 Vite로 자동 인식됩니다)
3. **Environment Variables**에 아래 두 개를 입력한 뒤 Deploy
   - `TEACHER_PASSWORD` : 교사 입장 비밀번호 (직접 정하세요. 6자리 이상 권장)
   - `GEMINI_API_KEY` : 0번에서 새로 발급한 키

### 3. 데이터 저장소(Upstash Redis) 연결
1. Vercel 프로젝트 > **Storage** 탭 > Create Database > **Upstash (Redis)** 선택
2. 지역은 가까운 곳(서울 또는 도쿄) 선택, 무료 플랜 선택 후 생성 > 프로젝트에 Connect
3. `KV_REST_API_URL`, `KV_REST_API_TOKEN` 환경변수가 자동으로 추가됩니다.
4. Deployments 탭에서 최신 배포의 `...` > **Redeploy** 로 다시 배포

### 4. 첫 사용
1. 배포된 주소(예: https://praise-relay.vercel.app) 접속
2. [교사 입장] > 비밀번호 입력 > 학생 명단 엑셀 업로드
3. 학생/학부모 기기에서 같은 주소로 접속


## 수업 진행 순서 (활동 흐름)
1. **칭찬 쓰기** : 학생들이 학생 화면에서 친구들에게 익명으로 칭찬을 씁니다.
2. **방송 시작** : 교사 > [방송 제어]에서 친구를 고르고 [방송 시작] → AI가 칭찬을 요약한 초안이 나오면 이름이 드러나지 않는지 확인(수정 가능)한 뒤 [이 내용으로 방송 시작]
3. **맞히기** : 학생 화면에 AI 요약만 나타나고, 학생들은 우리반 이름 중 1명을 골라 제출합니다. (제출한 뒤에도 정답 발표 전까지 바꿀 수 있어요.) 학부모 화면에는 요약과 제출 인원이 보입니다.
4. **정답 발표** : 교사가 [정답 발표]를 누르면 이름과 함께 **참여한 친구 중 맞힌 비율(%)** 이 나옵니다.
5. **응원 댓글** : 학생과 학부모가 발표된 친구에게 칭찬·응원 댓글을 남깁니다. 교사는 방송 화면과 [댓글 관리] 탭에서 댓글을 삭제할 수 있습니다.
6. **방송 종료** 후 다음 친구로 반복합니다.

> 정답(누구인지)과 칭찬 원문은 정답 발표 전까지 학생·학부모 기기로 전달되지 않습니다.


## 여러 학급(3개 반)에서 운영하기

한 학급씩 완전히 독립된 주소로 운영하는 것을 권장합니다. (한 반 데이터 문제가 다른 반에 영향을 주지 않아요.)

1. 이 저장소를 Vercel에서 **각 학급마다 별도 프로젝트로 3번 Import**합니다. (같은 GitHub 저장소를 여러 프로젝트로 가져올 수 있어요.)
   - 예: `praise-5-1`, `praise-5-2`, `praise-5-3` → 각각 `praise-5-1.vercel.app` 같은 주소가 생깁니다.
2. 각 프로젝트의 Environment Variables에 `TEACHER_PASSWORD`를 **학급마다 다르게** 설정하세요. (같은 비밀번호면 다른 반 교사도 들어갈 수 있어요.)
3. 각 프로젝트의 Storage 탭에서 **Upstash Redis를 각자 새로 만들어 연결**하세요. 이게 가장 확실한 분리 방법입니다.
4. (안전장치) 혹시 실수로 여러 프로젝트가 같은 Redis를 공유하게 되더라도 데이터가 섞이지 않도록, 환경변수 `CLASS_ID`에 학급마다 다른 값(예: `class-5-1`)을 넣어두세요. 모든 데이터 키 앞에 이 값이 자동으로 붙어서 서로 다른 학급의 데이터가 절대 겹치지 않습니다. 비워두면 `default`로 동작합니다.
5. 환경변수를 바꾼 뒤에는 **Redeploy**를 눌러야 적용됩니다.

## 수업 전 체크리스트
- [ ] 전날 리허설: 교사 1대 + 학생 역할 기기 2~3대로 칭찬 작성 → 방송 시작 → 이름 고르기 → 정답 발표 → 댓글까지 확인
- [ ] AI 요약이 정상적으로 나오는지 확인 (실패하면 친구들의 칭찬을 그대로 가져온 초안이 나오니 직접 다듬거나 [다시 만들기])
- [ ] 칭찬을 미리 충분히 모아두기 (칭찬이 1개 이상인 친구만 방송할 수 있어요)
- [ ] 리허설 데이터 삭제: 교사 > 학생 명단 > [칭찬·댓글 모두 지우기]
- [ ] 학생/학부모 접속 주소를 QR코드나 큰 글씨로 미리 준비
- [ ] 교실 와이파이가 불안하면 학생 기기는 LTE/5G로도 접속 가능한지 확인
- [ ] 교사 비밀번호와 주소를 수업 직전에 한 번 더 확인

## 참고
- 데이터는 Upstash Redis에 저장되며, 학생 정보는 학년·반·번호·이름뿐입니다.
- 맞힌 비율은 "답을 제출한 친구" 기준으로 계산합니다. (우리반 전체 인원 기준으로 바꾸려면 api/action.js 의 revealAnswer 에서 participants 대신 total 로 나누면 됩니다.)
- 화면은 3초마다 최신 데이터를 확인합니다. (서버는 2초 단위로 응답을 공유해서 접속자가 많아도 안정적입니다.)
- 사용할 Gemini 모델을 바꾸려면 환경변수 `GEMINI_MODEL`을 추가하세요. (기본값: gemini-3.1-flash-lite)
- 환경변수를 바꾼 뒤에는 반드시 Redeploy 해야 적용됩니다.

# 우리반 강점 찾기 — 강점 칭찬 · 추리 · 성찰 (Vercel 배포판)

React(Vite) 화면 + Vercel 서버 함수 + Redis(데이터 저장) + Gemini(AI 요약)로 구성되어 있습니다.
기존 Google Apps Script / 구글 시트는 더 이상 필요 없습니다.

## 배포 순서

### 0. (먼저!) 노출된 API 키 폐기
대화창에 붙여넣은 Gemini API 키는 이미 노출된 것으로 보고, Google AI Studio(aistudio.google.com) > API 키에서
**기존 키를 삭제하고 새 키를 발급**하세요. 새 키는 GitHub나 코드 어디에도 적지 말고 2번에서 Vercel에만 입력합니다.

### 1. GitHub에 올리기
1. github.com > New repository > 이름 `praise-relay`, **Private** 선택 > Create
2. 이 폴더의 압축을 풀고, 저장소 화면에서 `uploading an existing file`(또는 Add file > Upload files) 클릭
3. 압축 푼 폴더 **안의 파일과 폴더 전체**(api, src, package.json, index.html …)를 드래그해서 올리기
   - `package.json`이 저장소 맨 바깥(루트)에 보여야 합니다.
4. Commit changes

### 2. Vercel에 프로젝트 만들기
1. vercel.com > GitHub 계정으로 로그인 > Add New > Project
2. `praise-relay` 저장소 Import (Framework는 Vite로 자동 인식됩니다)
3. **Environment Variables**에 아래 두 개를 입력한 뒤 Deploy
   - `TEACHER_PASSWORD` : 교사 입장 비밀번호 (직접 정하세요. 6자리 이상 권장)
   - `GEMINI_API_KEY` : 0번에서 새로 발급한 키

### 3. 데이터 저장소(Redis) 연결
1. Vercel 프로젝트 > **Storage** 탭 > Create Database > **Redis** 선택 (Upstash Redis가 아니라 일반 **Redis**를 고르세요)
2. 무료 플랜(Free) 선택 후 생성
3. 오른쪽 위 **Connect to Project**를 눌러 이 프로젝트를 선택 (Custom Environment Variable Prefix 칸은 **비워두세요** — 값을 넣으면 연결이 안 됩니다)
4. `REDIS_URL` 환경변수가 자동으로 추가됩니다.
5. Deployments 탭에서 최신 배포의 `...` > **Redeploy** 로 다시 배포

> Vercel Storage에는 비슷한 이름의 상품이 두 가지 있어요. **Upstash Redis**(REST 방식)와 **Redis**(연결 문자열 방식)인데, 이 코드는 후자인 **Redis**(`REDIS_URL` 하나로 접속)에 맞춰져 있습니다. 이름을 헷갈리지 않도록 주의하세요.

### 4. 첫 사용
1. 배포된 주소(예: https://praise-relay.vercel.app) 접속
2. [교사 입장] > 비밀번호 입력 > 학생 명단 엑셀 업로드
3. 학생 기기에서 같은 주소로 접속


## 수업 진행 순서 (활동 흐름)
교사 화면의 [활동2] / [활동3] / [활동4] 탭에 있는 **시작 · 중지 버튼**으로 학생 기기 화면이 바뀝니다. (한 번에 하나의 활동만 진행돼요)

| 교사가 누른 버튼 | 학생 기기에 보이는 화면 |
|---|---|
| (아무것도 시작 안 함 / 중지) | **활동1 · 강점 칭찬 쓰기** |
| [활동2 시작] | **활동2 · 친구 맞히기** (상자가 열리기 전에는 안내 화면) |
| [활동3 시작] | **활동3 · 기분 나누기** |
| [활동4 시작] | **활동4 · 내가 아는 나 vs 친구가 본 나** |

1. **활동1 · 강점 칭찬 쓰기** : 먼저 *내가 생각하는 나의 장점 3가지*를 고르고(8가지 강점: 배려·성실·창의·유머·리더십·협동·용기·정직),
   친구에게는 **강점 1개 선택 + 상황 → 행동(필수, 5글자 이상) → 느낀 점** 순서로 구체적으로 칭찬을 씁니다. 모두 익명이에요.
2. **활동2 · 물음표 상자(추리)** : 한 명씩 앞으로 나와 상자를 누르면 **힌트 1(친구들이 고른 강점 키워드)** 이 먼저 나옵니다.
   근거를 들어 추리한 뒤 교사 화면의 **[힌트 2 열기]** 를 누르면 **AI 요약**이 공개되고, **[정답 확인]** 을 누르면 이름이 발표됩니다.
   (맞힌 비율은 표시하지 않아요. 힌트 2는 열기 전까지 학생 기기로도 전달되지 않습니다.)
3. **활동3 · 기분 나누기** : "칭찬을 듣고 난 후 나의 기분은 어떤가요?"에 학생이 문장으로 쓰면
   AI가 **감정 단어만** 뽑아 워드클라우드로 보여줍니다. 화면의 *함께 이야기해 봐요* 질문(들을 때 vs 해 줄 때, 쑥스러움, 진짜 칭찬 vs 아부)으로 토론할 수 있어요.
4. **활동4 · 나 vs 친구가 본 나** : 학생 기기에 *친구들이 찾아 준 강점 그래프*와 내가 예상한 장점이 함께 나타나고,
   "내가 몰랐던 내 장점 / 생각보다 적게 나온 장점 / 나도 알고 친구도 아는 장점"이 자동 분석됩니다.
   *새롭게 알게 된 점*과 *이번 주 실천 다짐*을 쓰면 **강점 카드**가 만들어지고 이미지(PNG)로 저장할 수 있어요.
   교사 화면에는 우리 반 전체 강점 분포 그래프가 나옵니다. (활동4에서는 칭찬 원문이 학생에게 보이지 않아요.)

> 정답(누구인지)과 칭찬 원문은 정답 확인 전까지 학생 기기와 교사 화면 어디에도 표시되지 않습니다.

## 여러 학급(3개 반)에서 운영하기

한 학급씩 완전히 독립된 주소로 운영하는 것을 권장합니다. (한 반 데이터 문제가 다른 반에 영향을 주지 않아요.)

1. 이 저장소를 Vercel에서 **각 학급마다 별도 프로젝트로 3번 Import**합니다. (같은 GitHub 저장소를 여러 프로젝트로 가져올 수 있어요.)
   - 예: `praise-5-1`, `praise-5-2`, `praise-5-3` → 각각 `praise-5-1.vercel.app` 같은 주소가 생깁니다.
2. 각 프로젝트의 Environment Variables에 `TEACHER_PASSWORD`를 **학급마다 다르게** 설정하세요. (같은 비밀번호면 다른 반 교사도 들어갈 수 있어요.)
3. 각 프로젝트의 Storage 탭에서 **Redis를 각자 새로 만들어 연결**하세요. 이게 가장 확실한 분리 방법입니다.
4. (안전장치) 혹시 실수로 여러 프로젝트가 같은 Redis를 공유하게 되더라도 데이터가 섞이지 않도록, 환경변수 `CLASS_ID`에 학급마다 다른 값(예: `class-5-1`)을 넣어두세요. 모든 데이터 키 앞에 이 값이 자동으로 붙어서 서로 다른 학급의 데이터가 절대 겹치지 않습니다. 비워두면 `default`로 동작합니다.
5. 환경변수를 바꾼 뒤에는 **Redeploy**를 눌러야 적용됩니다.

## 수업 전 체크리스트
- [ ] 전날 리허설: 교사 1대 + 학생 역할 기기 2~3대로 칭찬 작성 → 활동2 상자 열기 → 정답 확인 → 활동3 기분 쓰기까지 확인
- [ ] AI 요약이 정상적으로 나오는지 확인 (실패하면 친구들의 칭찬을 그대로 가져온 초안이 나오니 직접 다듬거나 [다시 만들기])
- [ ] 칭찬을 미리 충분히 모아두기 (칭찬이 1개 이상인 친구만 방송할 수 있어요)
- [ ] 리허설 데이터 삭제: 교사 > 학생 명단 > [칭찬·댓글 모두 지우기] (기분 기록도 함께 지워져요)
- [ ] 학생 접속 주소를 QR코드나 큰 글씨로 미리 준비
- [ ] 교실 와이파이가 불안하면 학생 기기는 LTE/5G로도 접속 가능한지 확인
- [ ] 교사 비밀번호와 주소를 수업 직전에 한 번 더 확인

## 참고
- 데이터는 Redis에 저장되며, 학생 정보는 학년·반·번호·이름뿐입니다.
- 맞힌 비율은 "답을 제출한 친구" 기준으로 계산합니다. (우리반 전체 인원 기준으로 바꾸려면 api/action.js 의 revealAnswer 에서 participants 대신 total 로 나누면 됩니다.)
- 화면은 3초마다 최신 데이터를 확인합니다. (서버는 2초 단위로 응답을 공유해서 접속자가 많아도 안정적입니다.)
- 사용할 Gemini 모델을 바꾸려면 환경변수 `GEMINI_MODEL`을 추가하세요. (기본값: gemini-3.1-flash-lite)
- 환경변수를 바꾼 뒤에는 반드시 Redeploy 해야 적용됩니다.
